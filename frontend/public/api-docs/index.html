GuguWiki 接口文档

按实现依赖和页面操作查看接口。前六组是 React → Java；后两组是 Java ↔ Python 内部接口。

当前 Java 仅实现认证链路；创建用户与其他业务接口是待实现契约。

建议实现顺序

  1. 准备 BCrypt 密码能力；本地开发需要首个管理员时，显式运行 AdminSeedTest。
  2. 登录查询 password_hash，用 BCrypt.verify 校验，成功后生成 Redis Token。
  3. 恢复拦截器读取 Token、核验账号并续期；登录拦截器仅保护业务 API，处理结束清理 ThreadLocal。
  4. 后续业务接口按需实现；创建用户目前仅是接口契约。

JSON 成功为 HTTP 200 / code 200；失败状态与 code 相同；HTTP 204 没有 Result 响应体。

本地开发管理员测试数据

仅显式设置 GUGUWIKI_SEED_ADMIN=true、GUGUWIKI_SEED_ADMIN_EMAIL、GUGUWIKI_SEED_ADMIN_PASSWORD 后单独运行 AdminSeedTest，才会在尚无 ADMIN 的本地数据库中创建管理员。应用启动和普通测试不会自动创建账号。

POST
1.1 认证

登录

1.1.1 基本信息

项目内容
请求路径/api/v1/auth/login
请求方式POST
鉴权公开
接口描述按邮箱读取账号及 password_hash，用 BCrypt 验证明文密码；账号启用且入口角色合法后，生成随机 Token，Redis 存 userId 并设置 30 分钟滑动过期。

1.1.2 请求参数

位置参数名类型是否必须备注
Bodyemailstring是登录邮箱
Bodypasswordstring是用户输入的明文密码，仅用于本次校验
BodyentryREADER | ADMIN是请求进入的页面类型；不授予角色

请求示例

POST /api/v1/auth/login HTTP/1.1
Content-Type: application/json

{
  "email": "reader@guguwiki.dev",
  "password": "<用户密码>",
  "entry": "READER"
}

1.1.3 响应数据

200 OK · Result（data: UserDto） · application/json

参数名类型是否必须备注
codenumber是成功为 200；失败时与 HTTP 状态码相同
dataUserDto是业务数据；无数据时为 null
messagestring | null是本次操作的反馈信息；无反馈时可为 null 或空字符串
tokenstring是随机登录凭证；仅登录成功响应返回，前端后续放在 Authorization 请求头
data.idstring是用户 ID
data.namestring是显示名称
data.emailstring是登录邮箱
data.roleREADER | ADMIN是服务端角色

响应示例

HTTP/1.1 200 OK
Content-Type: application/json

{
  "code": 200,
  "data": {
    "id": "user-reader",
    "name": "林同学",
    "email": "reader@guguwiki.dev",
    "role": "READER"
  },
  "message": "欢迎登录，林同学！",
  "token": "<随机登录 Token>"
}

主要错误：HTTP 400 = Result.code 400（参数无效）、HTTP 401 = Result.code 401（未登录）、HTTP 403 = Result.code 403（权限不足）

HTTP 状态码与关键业务规则

HTTP 状态 = Result.code场景说明
400参数或导入格式无效校验失败
401未登录或会话过期需要重新登录
403权限不足角色、文档或会话权限不足
404资源不存在也可用于隐藏资源存在性
409状态冲突修订号或快照冲突
500服务内部错误请求未完成
503依赖服务不可用必须拒绝或按规则降级
200证据不足请求成功，但返回固定弃答文本

统一响应

Java 对外普通 JSON 接口成功时返回 HTTP 200 和 Result.code=200；失败时 HTTP 状态码与 Result.code 使用相同数字（如 HTTP 401 对应 code=401），响应体为 {code,data:null,message}。code 是数字状态码，message 提供用户可读提示。成功但无响应体的操作（如退出登录、删除会话）返回 HTTP 204，不返回 Result。PDF 原件和 SSE 成功响应使用各自格式；这些接口发生错误时仍返回 JSON Result，且 HTTP 状态与 code 一致。Python 服务的 JSON 响应不使用 Java Result。

密码与登录态

本地管理员测试数据使用 BCrypt 哈希后写入 users.password_hash；未来创建用户时也须使用同一方案。登录时按邮箱查账号并用 BCrypt.verify 校验，不能再次 hash 后比较字符串。登录成功生成高熵随机 Token，Redis 的 login:token:{token} 只存 userId，TTL 为 30 分钟；请求携带 Authorization: <登录 Token>。恢复拦截器查 Redis、确认数据库账号仍启用并刷新 TTL；登录拦截器拒绝未登录业务请求。公开登录页面由前端路由提供，POST /auth/login 放行。请求完成清理 ThreadLocal，退出登录删除 Redis 键。管理员接口还要校验 ADMIN，资源接口还要校验归属和当前权限。

授权候选检索

读者的检索范围为全部已发布文档；管理员可查看草稿并管理全部内容。FTS 与 pgvector 两路 SQL 均须先限定 active_version_id 有效的已发布文档，再排序并截取 Top-K。禁止取全局固定 Top-K 后过滤。权限服务故障直接返回 HTTP 503 / code 503。

降级与弃答

仅单路召回故障且另一条链路授权成功、达到该路独立阈值、最少有效证据数与启用的覆盖判断时降级。FTS、向量、重排分数不能共用阈值；证据不足返回“知识库中没有足够的信息。”，不调用生成模型补全内部知识。

版本与撤权

文档新版本索引成功后，Java 原子切换 active_version_id。失败保留旧版，并拒绝同文档并发发布。下架或切换生效版本后，在线浏览、检索、PDF 和引用立即按新生效版本处理；历史回答中不再可访问的引用应隐藏，用户问题和审计保留。

实验快照

快照冻结已发布文档版本、切片/索引及语料指纹、数据集标注、模型环境；每次运行冻结全部检索参数与逐查询结果。运行中语料或标注变化可使快照失效；读取结果再次校验可访问的发布版本，在线检索不能用实验快照绕过发布状态。

SSE 与取消

每个事件都带 eventId、runId、conversationId、messageId、createdAt、type；SSE id 等于 eventId。取消经过 RUNNING → CANCEL_REQUESTED → CANCELLED；Java 保存已产生文本并通知 Python 协作停止。若先完成则保持 COMPLETED；前端轮询运行状态确认终态。

内部信任边界

Python 不接收用户 ID、角色或 Cookie，只持有短期随机 scopeToken。Java 每次检索均校验 scopeToken 与发布状态；内部服务凭据与 scopeToken 都必须验证。

状态枚举与 Mock

RunStatus：RUNNING、CANCEL_REQUESTED、CANCELLED、COMPLETED、FAILED。JobStatus：PENDING、RUNNING、SUCCEEDED、FAILED、INVALIDATED。Mock 场景切换和重置不是 HTTP 接口。
